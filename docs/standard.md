# Craftmentation documentation standard

## Purpose

The standard defines a predictable documentation experience while allowing each repository to include only relevant information.

## Core README order

1. Project identity and one-line description
2. Badges and key links, when meaningful
3. Overview
4. Features
5. Preview, when useful assets exist
6. Technology stack
7. Architecture, when it adds value
8. Requirements
9. Installation
10. Usage and examples
11. Configuration, when applicable
12. Testing
13. Deployment, when applicable
14. Roadmap, when maintained
15. Contributing
16. Support
17. Acknowledgements, when applicable
18. License
19. Authors / maintainers

## Rules

- The order is a default, not a requirement to include every section.
- Do not create empty headings.
- Prefer a working example over a long abstract explanation.
- Keep detailed guides in `docs/` and link to them from the README.
- Keep badges purposeful and ensure their targets are valid.
- Use relative links for files within the same repository.
- Use accessible alt text for images.
- Use fenced code blocks with an appropriate language identifier.
- Mermaid diagrams are optional and must represent the actual architecture.
